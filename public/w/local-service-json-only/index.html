網頁顯示失敗，伺服器卻已經照做了

我寫了一個跑在自己電腦上的小服務，它會改我硬碟裡的檔案。這種服務有一個很多人不知道的問題：你開的任何一個網頁，都能對它送請求。這篇講瀏覽器到底擋了什麼、沒擋什麼，以及為什麼我的服務只收 JSON。

裡面的結果都是用真的瀏覽器跑出來的，不是照規格推的。

問題在哪

我的服務開在 127.0.0.1:4480，只有這台電腦連得到。聽起來很安全，外面的人進不來。

但你的瀏覽器也在這台電腦上。你打開一個別人的網頁，那個網頁裡的程式是在你的瀏覽器裡跑的，所以它也連得到 127.0.0.1:4480。它可以寫：

fetch('http://127.0.0.1:4480/fix', { method: 'POST', body: '...' })

多數人以為瀏覽器會擋下這種「跨網站的請求」。它確實會擋，但擋的東西跟你想的不一樣。

    第一種和第四種伺服器我用真的瀏覽器驗過，結果在下面的表。其他兩種是照同一套規則演的。

    先看預設那一組：別人的網頁、純文字、伺服器收到什麼都解析。網頁那邊拿到的是「失敗」，但檔案已經被改了。這就是標題那句話。

    觀念一：瀏覽器擋的是「讀回應」，不是「送出去」

    網頁從很久以前就能對別的網站送表單，這是 HTML 本來就有的功能，瀏覽器沒辦法事後禁掉，不然一堆舊網站會壞。所以瀏覽器的規矩是這樣定的：

    • 表單送得出來的那種請求，照樣放行。 請求會真的送到伺服器。
    • 回應不給網頁讀。 除非伺服器明講「這個網站可以讀」，不然網頁的程式只會拿到一個錯誤。

    對「讀資料」的服務來說這就夠了，別人的網頁讀不到你的資料。但對「改東西」的服務來說完全不夠。請求送到的那一刻伺服器就動手了，網頁讀不讀得到回應根本不重要。

    所以在開發工具裡看到紅色的跨網站錯誤，只代表網頁沒讀到回應，不代表伺服器沒收到。

    觀念二：不像表單的請求，瀏覽器會先問

    表單送不出來的請求就不一樣了。這種請求以前的網頁做不到，所以瀏覽器可以定新規矩：先問伺服器同不同意，同意才送。

    這個「先問」叫預檢。瀏覽器會自己先送一個 OPTIONS 請求，內容是「有個網站想對你送這種請求，可以嗎」。伺服器沒有明確回答可以，正式的請求就不會送出去。伺服器連看都看不到它。

    重點在第一列。JSON 不是表單送得出來的格式，所以網頁要送 JSON，一定會先被瀏覽器問一次。

    觀念三：所以伺服器只收 JSON

    把兩個觀念接起來，做法就出來了。伺服器只做兩件事：

    // 1. 不是 JSON 就不收
if (!/^application\/json\b/i.test(req.headers['content-type'] || '')) {
  throw new HttpError(415, '只收 application/json');
}

// 2. 沒有回答任何預檢。OPTIONS 進來就是 404，沒有「可以」這句話
    • 別人的網頁用純文字送：不用預檢，送得到，但伺服器看到不是 JSON，不收。
    • 別人的網頁用 JSON 送：要預檢，伺服器不回答可以，瀏覽器就不送。

    兩條路都斷了。第二點是「什麼都不做」，不需要寫程式，只要記得不要加上允許跨網站的設定。

    注意那個很常見的漏洞長什麼樣子：伺服器自己把內容讀進來，直接 JSON.parse，沒看格式標頭。這時候網頁把一段 JSON 文字標成純文字送過來，瀏覽器當它是表單放行，伺服器照樣解析成功。上面小實驗的第一種伺服器就是這樣。

    那金鑰呢

    我的服務另外還要一把金鑰，放在 Authorization 標頭裡。別人的網頁不知道金鑰，光這一點就會被擋下來。那為什麼還要管 JSON？

    • 兩層互相補。 金鑰哪天不小心外流，或是某個入口忘了檢查金鑰，JSON 這一層還在。
    • 金鑰擋的是「不知道的人」，JSON 這層擋的是「不該來的地方」。 就算網頁猜對了金鑰，帶著 Authorization 標頭的請求也要先預檢，一樣送不出來。

    那我自己的油猴腳本為什麼送得到？它用的是瀏覽器外掛提供的送法，不是網頁的 fetch，不受這套規矩管。它本來就是我裝的，手上有金鑰，也用 JSON 送。

    三個常見的錯

    • 以為只聽本機就安全。 外面的人連不進來，但你瀏覽器裡的每個網頁都連得到。
    • 看到跨網站錯誤就以為擋住了。 那個錯誤是說網頁讀不到回應。改東西的請求可能已經做完了。
    • 為了讓錯誤消失，加一行「允許所有來源」。 很多教學會這樣教。這等於對預檢一律回答可以，JSON 這層保護就整個沒了。小實驗的第二種伺服器就是這樣。

    記一句話就好：會改東西的本機服務，只收 JSON，而且不要回答預檢。
