手寫一支改字工具：找字、換字、推上去

我有一個工具，在自己的網站上點一段字就能改掉原始碼。它有一千多行，但核心只有一件事：在專案裡找到那句話，換掉，推上去。這一頁帶你把核心自己寫出來，五關，寫完大約 60 行。

寫完你會有一支這樣用的程式：

node fix.js 專案資料夾 "立即免費開始" "先用再說"

它會在那個專案裡找到「立即免費開始」，換成「先用再說」，然後 commit、push。只有一處才改，有好幾處就列出來然後停。

規則只有一條：每一關先自己寫。卡住超過十分鐘再開「提示」，寫完再開「我的寫法」對照。直接看答案抄一遍，等於沒練。

進度

過一關就勾一關。勾選記在這台瀏覽器裡。

開始前：做一個練習場

不要拿真的專案練。下面這段會做出一個假網站 play，還有一個假的遠端 play.git，push 會推到那裡，弄壞了整個刪掉重做就好。

需要先裝好 Node 20 以上和 git。開一個空資料夾，在 Git Bash 裡貼上：

mkdir play && cd play
git init -q -b main
git config user.email you@example.com
git config user.name you
git config core.autocrlf false
printf '<h1>立即免費開始</h1>\n<p>了解方案</p>\n<p>了解方案</p>\n' > index.html
printf '關於我們\n' > about.txt
git add -A && git commit -q -m init
git init -q --bare -b main ../play.git
git remote add origin ../play.git
git push -q -u origin main
cd ..

做完之後資料夾裡有 play 和 play.git。你的 fix.js 開在它們旁邊。

練習場裡故意放了兩句一樣的「了解方案」，第 4 關會用到。

第 1 關

在一個檔案裡找字

寫一支程式，給它檔名和一段字，它告訴你那段字在檔案的第幾個位置，找不到就說找不到。
process.argvfs.readFileSyncindexOf

先玩一次：indexOf 回傳的是什麼

位置從 0 開始數。<h1> 佔了 0 到 3，所以「立」在第 4 個位置。找不到的時候回傳 -1，把要找的字改掉試試看。

驗收

node fix.js play/index.html "立即免費開始"
找到了，在第 4 個位置

node fix.js play/index.html "了解方案"
找到了，在第 19 個位置

node fix.js play/index.html "沒有這句"
找不到「沒有這句」
提示
  • process.argv 是一個陣列，前兩個是 node 自己和你的檔名，你打的參數從第三個開始。用 process.argv.slice(2) 把前兩個切掉。
  • fs.readFileSync(檔名, 'utf8') 會把整個檔案讀成一個字串。沒寫 'utf8' 拿到的不是字串，中文會出問題。
  • 字串找字用 內容.indexOf(要找的字)。
我的寫法 
const fs = require('node:fs');

const [file, from] = process.argv.slice(2);
const content = fs.readFileSync(file, 'utf8');
const at = content.indexOf(from);

if (at === -1) console.log('找不到「' + from + '」');
else console.log('找到了，在第 ' + at + ' 個位置');

第 2 關

換掉並存檔

多收一個參數「新的字」。找到之後把舊字換成新字，寫回檔案。
slicefs.writeFileSyncprocess.exit

先玩一次：為什麼不用 replace

換字最直覺的寫法是 內容.replace(舊字, 新字)。它有一個坑：新字裡的 $ 有特殊意思。下面兩種寫法同時跑給你看。

replace
slice 接起來

在 replace 的新字裡，$& 代表「被換掉的那段字」，$$ 代表一個 $。你要寫的是價錢，它卻當成指令。新字是人打的，什麼符號都可能出現，所以改用位置直接切：前半段、新字、後半段，三塊接起來。這樣新字裡寫什麼就是什麼。

驗收

node fix.js play/index.html "立即免費開始" "先用再說"
改好了

git -C play diff
-<h1>立即免費開始</h1>
+<h1>先用再說</h1>

看完用這行還原，下一關還要用原本的字：

git -C play checkout -- index.html
提示
  • 內容.slice(0, 位置) 是舊字前面的全部。
  • 舊字後面從哪裡開始？位置加上舊字的長度。
  • 找不到就不該繼續往下寫檔。印完訊息用 process.exit(1) 結束，1 代表「沒成功」。
我的寫法 
const fs = require('node:fs');

const [file, from, to] = process.argv.slice(2);
const content = fs.readFileSync(file, 'utf8');
const at = content.indexOf(from);

if (at === -1) {
  console.log('找不到「' + from + '」');
  process.exit(1);
}

const next = content.slice(0, at) + to + content.slice(at + from.length);
fs.writeFileSync(file, next, 'utf8');
console.log('改好了');

第 3 關

在整個專案裡找

第一個參數從「檔名」改成「專案資料夾」。寫一個函式 filesWith(字)，回傳專案裡有這段字的所有檔名。這一關先只印出檔名，不用改字。
child_process.execFileSyncgit greptry / catch

自己一個一個資料夾去讀檔也做得到，但要自己跳過 node_modules、圖片、建置出來的檔案。git 本來就知道哪些檔案是專案的，叫它找最省事：

git grep -l -F -z -e "了解方案"
  • -l：只列檔名，不列內容。
  • -F：把要找的字當普通文字，不要當成規則運算式。字裡有 . 或 ( 才不會出事。
  • -z：檔名之間用一個看不見的 0 字元隔開，不用換行。中文檔名才不會被改寫成一串跳脫碼。
  • -e：後面接的就是要找的字。字剛好是 - 開頭也不會被當成選項。

驗收

node fix.js play "了解方案"
[ 'index.html' ]

node fix.js play "關於我們"
[ 'about.txt' ]

node fix.js play "沒有這句"
[]

第三個最容易卡住：找不到的時候程式會直接壞掉。看提示之前先自己查為什麼。

提示
  • execFileSync('git', ['grep', ...], { cwd: 專案資料夾, encoding: 'utf8' })。cwd 是「在哪個資料夾跑」，encoding 讓它回傳字串。
  • 參數用陣列一個一個給，不要自己拼成一整串指令。字裡有空白或引號時，拼字串會被拆錯。
  • git grep 找不到東西時，結束碼是 1。execFileSync 看到結束碼不是 0 就丟錯誤。所以要用 try / catch 接住，看 err.status === 1 就回傳空陣列，其他錯誤照樣丟出去。
  • -z 的輸出用 .split('\0') 切開，最後會多一個空字串，用 .filter(Boolean) 拿掉。
我的寫法 
const { execFileSync } = require('node:child_process');

const [repo, from] = process.argv.slice(2);

// 在專案資料夾裡跑一個 git 指令，回傳它印出來的字
function git(...args) {
  return execFileSync('git', args, { cwd: repo, encoding: 'utf8' });
}

function filesWith(words) {
  try {
    return git('grep', '-l', '-F', '-z', '-e', words).split('\0').filter(Boolean);
  } catch (err) {
    if (err.status === 1) return [];   // 找不到，不是壞掉
    throw err;
  }
}

console.log(filesWith(from));

多包一層 git() 是因為第 5 關還要叫三次 git，到時候直接用。

第 4 關

好幾處就停

把前三關接起來：找出所有出現的地方。剛好一處就換掉，零處或好幾處就印出原因然後停，一個字都不改。
whileindexOf 的第二個參數path.join

這一關是整支程式最重要的判斷。改錯地方比沒改更糟，所以只要不確定是哪一處，就不動手。

注意同一個檔案裡也可能出現兩次。filesWith 只告訴你哪些檔案有，沒說有幾處，所以每個檔案還要自己數。

驗收

node fix.js play "了解方案" "看價錢"
有 2 處一樣的字，不知道要改哪一個：
  index.html 第 2 行
  index.html 第 3 行

node fix.js play "沒有這句" "x"
找不到「沒有這句」

node fix.js play "立即免費開始" "先用再說"
改好了：index.html 第 1 行

前兩個跑完，git -C play status 應該是乾淨的。第三個跑完先不要還原，第 5 關直接接著做。

提示
  • indexOf(字, 從哪裡開始找)。找到一處之後，從那一處的後面再找一次，直到回傳 -1。
  • 把每一處記成一個物件放進陣列：哪個檔、位置、第幾行、檔案內容。最後看陣列長度是 0、1 還是更多。
  • 第幾行怎麼算：位置前面有幾個換行，再加 1。內容.slice(0, 位置).split('\n').length 剛好就是。
  • git grep 給的檔名是相對於專案資料夾的，讀檔時要用 path.join(專案資料夾, 檔名) 接起來。
我的寫法 
// 這段字在一個檔案裡出現在哪些位置
function positions(content, words) {
  const found = [];
  let at = content.indexOf(words);
  while (at !== -1) {
    found.push(at);
    at = content.indexOf(words, at + words.length);
  }
  return found;
}

const hits = [];
for (const file of filesWith(from)) {
  const content = fs.readFileSync(path.join(repo, file), 'utf8');
  for (const at of positions(content, from)) {
    const line = content.slice(0, at).split('\n').length;
    hits.push({ file, at, line, content });
  }
}

if (hits.length === 0) {
  console.log('找不到「' + from + '」');
  process.exit(1);
}
if (hits.length > 1) {
  console.log('有 ' + hits.length + ' 處一樣的字，不知道要改哪一個：');
  for (const h of hits) console.log('  ' + h.file + ' 第 ' + h.line + ' 行');
  process.exit(1);
}

const hit = hits[0];
const next = hit.content.slice(0, hit.at) + to + hit.content.slice(hit.at + from.length);
fs.writeFileSync(path.join(repo, hit.file), next, 'utf8');
console.log('改好了：' + hit.file + ' 第 ' + hit.line + ' 行');

第 5 關

commit 和 push

改完之後，只把改到的那一個檔案 commit，然後 push。
git addgit commit -mgit push

你的網站如果是 push 了就自動部署，這一步做完網站就會開始更新。這支程式不用管部署，它的工作到 push 為止。

驗收

node fix.js play "關於我們" "我們是誰"
改好了：about.txt 第 1 行
推上去了

git -C play.git log --oneline
xxxxxxx 改字：「關於我們」→「我們是誰」
xxxxxxx init

第二行看的是 play.git，也就是假的遠端。那裡看得到你的 commit，才代表真的推出去了。中間 git 自己還會印一兩行 To ../play.git，那是正常的。

第 4 關最後改的 index.html 還沒 commit，這是故意留著的。跑完這一關用 git -C play status 看一下，它應該還在「已修改」裡，沒有被一起帶進這次的 commit。這就是下面提示第一條的用意。

提示
  • git add 後面接那一個檔名，不要用 git add -A。專案裡可能有你正在改到一半的別的檔案，不該被一起送出去。
  • commit 訊息一樣用陣列參數傳：git('commit', '-m', 訊息)。訊息裡有引號和中文都不用特別處理。
  • 三個指令任何一個失敗，execFileSync 都會丟錯誤讓程式停下來，後面的不會繼續跑。這裡正好就是要這樣。
我的寫法 
git('add', hit.file);
git('commit', '-m', '改字：「' + from + '」→「' + to + '」');
git('push');
console.log('推上去了');

全部跑一次

把練習場刪掉重做一份，照順序跑這四行。四行都對，這支就寫完了。

const fs = require('node:fs');
const path = require('node:path');
const { execFileSync } = require('node:child_process');

const [repo, from, to] = process.argv.slice(2);
if (!repo || !from || !to) {
  console.log('用法：node fix.js <專案資料夾> "舊字" "新字"');
  process.exit(1);
}

function git(...args) {
  return execFileSync('git', args, { cwd: repo, encoding: 'utf8' });

  } catch (err) {

  while (at !== -1) {

    at = content.indexOf(words, at + words.length);

這支還不會的事

拿去改真的網站，很快會遇到下面這些。每一項都是之後可以自己加的一關。

  • 同一句話出現很多次。 現在是直接停。要能挑對那一處，得知道那句話前後還有什麼字，拿去跟原始碼的上下文比。
  • 新字裡有引號或大括號。 字如果寫在程式碼的字串裡，多一個引號整個檔案就壞了。要先檢查新字有沒有這類符號。
  • 本機的專案比遠端舊。 push 會被拒絕。改之前要先 git pull --ff-only。
  • 那個檔案你自己正改到一半。 這支會把你還沒做完的修改一起 commit 出去。改之前要先看那個檔案乾不乾淨。
  • 字不在原始碼裡。 從資料庫來的、程式拼出來的字，這個做法找不到，也不該找到。

下一步是把這支包成一個只聽本機的小服務，再寫一段在網頁上跑的腳本，點一下字就把「舊字、新字」送過來。那時候核心還是這 60 行。
