上傳彈窗一出來，游標就不見了

DuckShot v1.2.6 修的這個 bug 只動了 16 行 CSS，但裡面有三個值得記住的觀念：假游標、圖層順序、選擇器的權重。先動手玩，再往下看原因。

為什麼截圖時要把真游標藏起來

DuckShot 按下快捷鍵後，會先抓一張整個螢幕的畫面，再蓋上一層全螢幕的覆蓋層讓你框選。如果這時候滑鼠游標還在，它會被一起抓進圖裡。所以覆蓋層用一條規則把游標整個關掉：

body.hide-cursor,
body.hide-cursor * {
  cursor: none !important;   /* 覆蓋層裡每一個元素都沒有游標 */
}

沒有游標就沒辦法瞄準，所以另外畫了一個「假游標」：一個橘色圓點加上十字線，其實只是普通的 div，用 mousemove 事件跟著滑鼠跑。它設了 pointer-events: none，所以點擊會穿過它，落在底下真正的按鈕上。

觀念一：誰蓋住誰，看 z-index

覆蓋層裡的東西是一層一層疊起來的，z-index 數字越大越上面。上傳彈窗是後來才加的功能，為了確保它蓋住所有東西，數字給了 2000，比假游標的 1005 還大。

2000
上傳彈窗整片半透明黑幕加中間的白色卡片
1005
假游標（橘色圓點和鴨鴨）被彈窗壓在下面：黑幕上變很暗，白色卡片上完全看不到
1004
十字對齊線
更低
選取框、工具列、凍結的螢幕畫面

於是兩件事同時成立：真游標被 cursor: none 關掉了，假游標又被彈窗蓋住。兩個都沒了，使用者就看不到自己指在哪裡。單看任何一段程式都沒有錯，是兩個功能疊在一起才出事。

觀念二：兩條都寫 !important 時，比誰的選擇器比較具體

修法是「彈窗裡面把真游標還回來」。但原本那條規則有 !important，新規則光寫 cursor: default 會輸。兩邊都有 !important 的時候，瀏覽器比的是選擇器的權重，算法是數裡面有幾個 class、幾個標籤名稱：

選擇器class 數標籤數結果
body.hide-cursor *11原本的規則（* 不算分）
body.hide-cursor .upload-modal.show *31class 比較多，贏
body.hide-cursor .upload-modal.show button32再多一個標籤，蓋過上一條
 
/* 彈窗和裡面所有東西：還原成一般箭頭 */
body.hide-cursor .upload-modal.show,
body.hide-cursor .upload-modal.show * {
  cursor: default !important;
}
/* 可以點的東西：手指 */
body.hide-cursor .upload-modal.show button,
body.hide-cursor .upload-modal.show .link-value {
  cursor: pointer !important;
}

這時候把真游標放出來是安全的：螢幕畫面在彈窗出現之前早就抓好凍結了，游標不會再被拍進去。

觀念三：用 :has() 讓「裡面的狀態」影響「外面的元素」

真游標回來之後，假游標還留在彈窗底下的黑幕上，會變成同時有兩個游標。要在彈窗打開時把假游標收起來，但假游標不在彈窗裡面，一般的選擇器只能往內選，選不到它。

:has() 可以反過來問：「這個 body 裡面，有沒有一個正在顯示的彈窗？」有的話，再去選 body 底下的假游標：

body.hide-cursor:has(.upload-modal.show) .duck-cursor,
body.hide-cursor:has(.upload-modal.show) .crosshair-line {
  display: none !important;
}

好處是完全不用改 JavaScript。彈窗有四個地方會開關（上傳中、成功、失敗、點背景關閉），如果用 JS 去加減 class，四個地方都要記得寫；用 CSS 直接跟著 .show 走，以後再多幾個開關的地方也不會漏。

為什麼不直接把假游標的 z-index 調到 2001

  • 這樣也能看到游標，但白色對話框上會跑著一個瞄準用的十字線和圓點，看起來很怪。
  • 對話框是一般的介面，使用者預期的是箭頭和手指。手指游標還能告訴他哪裡可以點，假游標做不到。
  • 假游標存在的理由是「不要被拍進截圖」，彈窗出現時這個理由已經不存在了。

怎麼確認真的修好

開一個看不見的視窗，分別載入修改前和修改後的頁面，把彈窗打開，直接問瀏覽器「這個元素現在算出來的游標是什麼」（getComputedStyle(el).cursor）。這比用眼睛看可靠，也不用動到你正在用的 DuckShot。
